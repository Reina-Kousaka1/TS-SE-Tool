## Architecture self-review — bounded local snapshot reads (2026-11-26)

No Architect tool is available. This implementation-agent self-review follows `AGENTS.md`; it is not an independent review. `LocalSnapshotStore` now reads through a bounded stream path: seekable inputs are checked against their remaining length and probed for growth, short reads are rejected, and non-seekable inputs consume at most the configured limit plus one detection byte. The caller retains stream ownership. Regression tests cover stopping at the first overflow byte, accepting an exact-size stream, detecting growth after an initial length report, and preserving stream ownership. Oversized stored history is rejected on read, while append reports `snapshot_file_too_large` without replacing existing history. This hardening only bounds this snapshot-file read path; it does not establish cross-process consistency for same-size concurrent rewrites or validate game-save formats. ## Architecture self-review — bounded transaction hashing (2026-11-26)

No Architect tool is available. This implementation-agent self-review follows `AGENTS.md` and is not an independent review. `AtomicFileTransaction` previously checked a target's `FileInfo.Length` before calling `SHA256.HashDataAsync`, which then read to EOF. A file that grew between those operations could exceed the transaction's 128 MiB payload limit during hashing. The transaction now hashes via a fixed 64 KiB buffer and incremental SHA-256, reading at most the remaining permitted bytes plus one detection byte; the same helper is used for original, staged, backup, and post-commit file hashes. Synthetic tests verify exact-limit SHA-256 output, rejection after the first overflow byte, and that the caller's stream remains open. This bounds bytes consumed and hashing memory; it does not make filesystem path checks atomic or detect same-size concurrent rewrites. The .NET 10 matrix [45808106158](https://github.com/Reina-Kousaka1/TS-SE-Tool/actions/runs/45808106158) passed 104/104 tests on each of five desktop targets and 95/95 on both Fedora targets. - The interface ships embedded English and German text resources. It follows the operating-system UI culture at startup and falls back to English for other cultures; Settings shows the resolved language. A language change requires restarting the app.

- No profile scanning or real game-save reading is enabled. Save writes, restore actions, and background profile monitoring are disabled.

## Retained foundation and savegame safety

The SII syntax document and atomic file transaction remain intact. The parser preserves source text and supports a narrow update to an existing unique field; its bounded parser has configurable limits for source characters, line count/length, block count, field count, and nesting depth. `ParseReader` caps consumption at the configured character limit plus one detection character and rejects overlong lines while scanning input; callers retain ownership of the reader. The string parser can only reject after its input string already exists. These defaults are defensive resource caps, not game-format facts, and have not been validated against real saves. The parser does not implement complete SII semantics, compressed save containers, or game-version schemas. The transaction snapshots caller-supplied bytes, validates and stages that same stable private snapshot, checks the original SHA-256, retains a backup, and reports uncertain outcomes as `RecoveryRequired`. `AtomicFileRecoveryInspector` provides a read-only, per-target inventory of candidate `.tmp` and `.bak` artifacts after an interrupted process. It matches the transaction's exact filename convention, inspects top-level metadata only, refuses reparse-point targets/directories, and returns an incomplete result when its directory-entry or artifact limits are reached. It does not read artifact contents, prove their provenance, restore files, or delete them; operator-reviewed recovery remains unimplemented.

`GameAdapterRegistry` starts empty. No game or save version is verified for reading or writing, so the UI cannot open or edit a production profile. The analytics library keeps recorded transactions distinct from snapshot-derived balance differences; it has no profile-backed history in the desktop app. Snapshot deltas require a stable `ProfileId`; older local snapshots without one remain readable but are excluded from delta calculations. Callers must also scope transaction inputs to one profile because transaction records do not carry profile identity.

The parser has only synthetic fixtures. The referenced [PR #147](https://github.com/LIPtoH/TS-SE-Tool/pull/147) reports local roundtrips over 21 ATS v97 saves, but its 64 changed files include no save-format fixtures, so that result cannot be reproduced from the PR. [PR #149](https://github.com/LIPtoH/TS-SE-Tool/pull/149) describes an ETS2 1.61 compatibility update and says ATS was not tested; its 1,318 changed files also include no save-format fixtures. Neither report is treated as compatibility evidence for this foundation, and no code was copied from them. Genuine ETS2/ATS saves, mods, Coaches DLC, unknown-field roundtrips, and complete serializer behavior remain unverified. A successful generic atomic transaction is not evidence of a safe game-save edit.

The [official GitHub-hosted runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) lists `macos-latest`, `macos-15`, `macos-26`, and `xcode-27` as standard M1 ARM64 labels, and notes that macOS jobs may take longer to start under high demand. The documentation does not promise that changing between these aliases selects a separate capacity pool. The explicit `macos-15` run [45795444731](https://github.com/Reina-Kousaka1/TS-SE-Tool/actions/runs/45795444731) ended before runner assignment or any step; an alias-only retry would not be a diagnosed fix, so the workflow was not changed to guess another label. The exact GitHub orchestration cause remains unknown. A configured larger runner may require a paid plan, while a self-hosted runner is not configured; neither was introduced.
